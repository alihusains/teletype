# Teletype QA audit: end-user journey findings

Date: 2026-09-27
Scope: every feature in the shipped user journey, first launch to insights.
Method: five parallel read-only audits over disjoint areas, plus executable
smoke tests written to reproduce what the audits claimed.

Every S1 was independently re-verified by running the real code. Findings
marked **[repro]** have a test in this repo that demonstrates them, in two
forms: a green test pinning today's wrong output, and an `#[ignore]`d
acceptance test that defines the fix.

---

## Read this first

The three most damaging defects are not the subtle ones. They are:

1. **Every dictated price is corrupted.** `itn::normalize` welds the number
   onto the previous word: "it will cost fifty dollars" becomes
   `"it will cost$50"`. This fires on every currency amount, percentage,
   decimal, time and date in ordinary speech, and it is the *default* path.
2. **Saying the word "period", "comma", "star", "quote" or "plus" in a
   sentence types a symbol instead.** "the payment period ends in March"
   becomes `"the payment. ends in March"`.
3. **The Insights screen can hold a lock for 64 seconds and delay your text
   landing in the document.** Measured, not estimated.

Each is a one-to-few-line fix. None was caught by 446 unit tests or by
`tsc --noEmit`, because all three corrupt text *in ways that keep the words
present*, which is exactly what coarse assertions cannot see.

# S1: ship blockers

## 1. [repro] ITN welds every number onto the previous word

`crates/teletype-core/src/itn.rs:544, 560, 567, 580, 613, 628`

Every affected pass starts its match with `\s` and the replacement never
re-emits it. Verified against the real `itn::normalize`:

| You say | You get |
|---|---|
| it will cost fifty dollars | `it will cost$50` |
| i paid ninety nine dollars | `i paid$99` |
| that is one hundred percent right | `that is100% right` |
| the meeting is at five pm | `the meeting is at5:00 PM` |
| the ratio is one point five to one | `the ratio is1.5 to one` |
| lets meet on march twelfth two thousand seven | `lets meet onMarch 12, 2007` |

`numeric_ranges` (`itn.rs:806`) shows the correct shape: it captures a `lead`
group and puts it back. Apply that to the six broken passes.

**Why S1:** it corrupts every price, percentage, decimal, time and date in
normal speech, on the default path, invisibly. The user checks their work, or
does not, and either way the wrong number is in the document.

## 2. [repro] The decimal pass eats the start of the next word

`crates/teletype-core/src/itn.rs:541, 544`

`digit_alt` has no `\b` on the `o`/`oh` alternatives or on the repeated group,
so `out` = `o` + `ut`, `ones` = `one` + `s`:

| You say | You get |
|---|---|
| the reading is nine point eight on the Richter scale | `the reading is9.80n the Richter scale` |
| i rate it one point five out of five | `i rate it1.50ut of five` |
| one point out of ten | `1.0ut of 10` |
| three point ones | `3.0nes` |

Ratings and measurements are spoken constantly. Add `\b` to every alternative.

## 3. [repro] The years pass rewrites cardinal numbers as years

`crates/teletype-core/src/itn.rs:672-703`

The only rejections are a leading scale word and a following number word, so
`people`, `bucks`, `old` and `page` all pass:

| You say | You get |
|---|---|
| she is twenty one | `she is 2001` |
| he is twenty six years old | `he is 2006 years old` |
| we have twenty three people coming | `we have 2003 people coming` |
| twenty five bucks | `2005 bucks` |
| page twenty three | `page 2003` |
| it took two thousand and five dollars | `it took 2000 and$5` |

The module doc at `itn.rs:14` promises "ambiguous minimal pairs are left
spelled for the AI-polish layer". This does the opposite.

## 4. [repro] System AutoText rewrites ordinary English into symbols

`crates/teletype-core/src/autotext/system.rs:35-441`, `autotext/expand.rs:151-165`

`DEFS` contains bare common nouns and `expand_snippets_with` matches any
whole-word occurrence, unconditionally, with no setting gate. All 79 entries
are passed on every voice dictation (`dictation.rs:1000`):

| You say | You get |
|---|---|
| the payment period ends in March | `the payment. ends in March` |
| use a comma to separate the fields | `use a, to separate the fields` |
| the star of the show | `the * of the show` |
| the quote in the article was wrong | `the " in the article was wrong` |
| that is a plus for the team | `that is a + for the team` |
| start a new line for the address | `start a\nfor the address` |

Worse, `protect_snippets_with` runs first (`pipeline.rs:169`), so the model is
asked to "polish" the corruption: it saw `the payment{{AUTOTEXT_0}} ends in
March`.

**Fix:** require an explicit opt-in per entry, or restrict `DEFS` to phrases
that cannot be ordinary words ("smiley face" not "smile").

## 5. [repro] The personalization loop panics and permanently wedges dictation

`crates/teletype-desktop/src/dictation.rs:1291`, `edit_watch.rs:142`

`diff` returns `at = value.find(inserted)`, an offset into the **whole focused
field**. The caller slices `inserted` with it:

```rust
let user_text = format!("{}{}", &pending.inserted[..at], replacement);
```

`inserted` is only what Teletype typed, so `at` is routinely larger than it and
routinely lands inside a multi-byte character. Clicking into the middle of a
paragraph and dictating panics; so does any dictation containing an emoji.
When `at == 0` there is no panic, but the learner is handed only the user's
edit and never sees the dictated words.

The panic is caught by the per-event `catch_unwind` (`dictation.rs:95-100`),
which only logs. Because `observe_pending_edit` runs at line 871, *before*
`self.phase = Phase::Transforming` at line 880, the phase is still
`Transcribing`, `next_id` is already bumped, and the pipeline worker was never
spawned. No input can leave `Transcribing` (`state.rs:101` and `state.rs:131`
both return `Nothing`). The user loses the dictation outright, with no
injection, no history entry, no archive line, and a pill stuck on
"Transcribing..." until they force-quit. Notes, Mail and TextEdit all expose
`focused_text()`, so this is the common path.

**Fix:** `format!("{pending.inserted}{replacement}")`. `at` is not part of the
answer; `value[at..]` is the same string.

## 6. Your OpenAI API key is sent to whatever host you type

`crates/teletype-desktop/src/commands.rs:39-47`

```rust
fn read_api_key(base_url: &str) -> Option<String> {
    let host = secret_account_for_url(base_url);
    if host != "openai" {
        if let Some(key) = crate::secrets::get_secret(&host).ok().flatten() {
            return Some(key);
        }
    }
    crate::secrets::get_secret("openai").ok().flatten()   // unconditional
}
```

Point the connector at Groq, OpenRouter or LM Studio and the `sk-...` in your
keychain goes to that host as `Authorization: Bearer`. It fires on every app
launch (`rehydrate_provider:1319`), every `test_llm_connection:1279`, and
every `select_openai_provider:1228` probe.

`secret_account_for_url` also mishandles userinfo: for
`https://user:pass@evil.example/v1` it yields the account `"user"`, no key
exists for that, so the fallback returns the OpenAI key and it is sent to
`evil.example`.

Third-party credential disclosure triggered by ordinary UI use, with no log
line and no indication of which key was used. Contradicts D004 and D003.

**Fix:** remove the fallback (it is a P0-9 migration shim; migrate the keyring
account once instead) and parse the host with `url::Url`.

## 7. [repro] A model refusal replaces every word you said

`crates/teletype-core/src/transforms/validator.rs:78-168`

> You dictate "the quarterly review is on friday morning". The model replies
> "I'm sorry, I can't help with that." That sentence is typed into your
> document. Every word you said is gone, and there is no error.

Every existing check misses it: `"i'm sorry"` is not in `PREAMBLES` (line 57);
the echo check runs but only fires when the output shares 90% of its length
with the input, and a refusal shares nothing; the preamble guard at line 138
only rejects a preamble whose remainder looks like content; it is shorter than
the input, so neither the growth cap (line 148) nor the truncation floor (line
155, needs 80+ chars) applies.

The module doc at lines 5-6 states the contract this breaks: "On failure the
pipeline falls back to the original input, never to the model's raw output."
There is no `Failure` variant that can express "off-topic".

**Fix:** add a content-overlap check above some input floor: require the
output to share a minimum fraction of the input's content words (AutoText
placeholders excluded). Add `Failure::OffTopic`.

## 8. [repro] Any upgrade that adds a field silently wipes user data

| Struct | File | Fields without `#[serde(default)]` |
|---|---|---|
| `AutoTextEntry` | `autotext/mod.rs:54` | `description`, `scope`, and 6 more (only `snippet`/`system` are defaulted) |
| `TransformDefinition` | `transforms/mod.rs:14` | all 12 |
| `StyleProfile` | `style.rs:16` | all 6 |
| `Preference` | `personalization/mod.rs:69` | all 8 |
| `ScratchEntry` | `scratchpad.rs:12` | all 3 |

`JsonStore::load` (`storage.rs:33-49`) renames an unparseable file to
`.corrupt` and returns the default. A user upgrading across a build that added
or renamed any field comes back to an **empty AutoText library, no custom
transforms, no style profiles, no preferences, no scratchpad**, with no error
and no undo. The only trace is an `eprintln!`, which per Gotcha G002 can itself
abort the app.

`PROJECT_BRAIN.md` §6 claims "Settings fields are serde-defaulted for backward
compatibility". That holds for `Settings`, `Dictionary`, `UsageStats` and
`Scratchpad` (verified) and is **not implemented** for the five structs above.
The residual hazard for the defaulted ones is a *type* change rather than an
added field.

## 9. The Insights screen can block dictation for 64 seconds

`crates/teletype-core/src/insights.rs:276-290`, `crates/teletype-desktop/src/commands.rs:2112-2138`

The `subsumed` filter is O(distinct 2-grams × all n-grams) `str::contains`
calls, and `get_insights` holds the `history` mutex across the whole call. The
dictation worker takes that same mutex (`dictation.rs:1104`) *before* it
injects (`dictation.rs:1165`). Measured on this machine with a realistic
corpus (2,000-word vocabulary, 30-word entries):

| History entries | `insights::compute` |
|---|---|
| 100 | 0.67 s |
| 250 | 3.97 s |
| 500 | 16.1 s |
| 1000 (the `MAX_ENTRIES` cap) | **64.4 s** |

Clean quadratic. The user releases the hotkey, the pill says "Transforming...",
and the text lands in their document up to 64 seconds later, possibly after
they have switched windows. `HomeScreen.tsx:78` re-fires `get_insights` on
every dictation state change, so it compounds. The Dictation tab freezes solid
at the same time.

**Fix:** clone under the lock, release, then compute. That alone removes the
dictation stall. Then replace the `contains` sweep with a precomputed set.

## 10. [repro] The Insights headline is a fabricated number

`crates/teletype-core/src/insights.rs:179-192`

`wpm = total_words / (total_words / 150)`, integer division, a function of the
word count alone. No duration is recorded anywhere, so it cannot be a
measurement. Measured:

| words | app claims | shown as |
|---|---|---|
| 149 | 150 wpm | 4x faster, 3 min saved |
| 150 | 150 wpm | 4x faster, **2 min saved** |
| 290 | **290 wpm** | **7x faster** |
| 449 | 224 wpm | 6x faster |
| 1000 | 166 wpm | 4x faster |

At 290 words the app tells the user they speak at 290 wpm, which is
physically impossible. And **time saved goes down** as you dictate more
(149 words: 3 min; 150 words: 2 min). This is the marketing headline at
`InsightsScreen.tsx:505`.

**Fix:** record the actual recording duration per dictation and compute a real
rate. Until then, label it an estimate and drop the wpm and "Nx faster" claims
entirely; the time-saved number is defensible without them.

## 12. Dictated text is typed twice when the app normalises it

`crates/teletype-desktop/src/ax_text.rs:270-292`

The module contract is that `false` means "nothing was written, fall back to
the clipboard" (lines 15-19). Two of the three `false` returns fire *after* a
successful write.

> You dictate "don't stop" into any field with smart quotes. The write lands,
> the field normalises the apostrophe, the read-back returns `don’t `. The
> comparison fails, the function returns `false`, the caller pastes again, and
> the field now reads **`don't stop don't stop`**.

**Fix:** return an enum distinguishing "wrote nothing" from "wrote and the app
transformed it". The latter is success.

## 13. Selecting a local model kills every llama-server on your machine

`crates/teletype-inference/src/server.rs:549-567`

`pgrep -f llama-server` matches the full argv of *any* process, then `kill`s
every pid that is not the app's own. If you run your own `llama-server`, or use
LM Studio, and then click Select on a local model, your server is killed. The
doc comment claims "at most one of our servers should be running at a time" and
"we identify ours by command name only" - both are the bug. The `pid == me`
check guards the app, not the child, so a recycled pid is also killed.

Two Teletype instances (installed app plus `cargo tauri dev`, the documented
dev setup) kill each other's servers, and the loser's provider still reports
`is_ready() == true` while every transform silently returns connection-refused.

**Fix:** own the child pid from `Child::id()`. Kill by pid, never by name.

## 14. Dictating destroys a copied file on your clipboard

`crates/teletype-core/src/injector.rs:101-112, 143-160`

`restore_clipboard` defaults to **true** (`commands.rs:283`). The save path
reads text, then image, and everything else becomes `Saved::Empty`; the restore
path then calls `clipboard.clear()`.

> Copy a file in Finder (pasteboard holds `public.file-url`, no text, no
> image). Dictate a note. Your copied file is gone. Cmd-V pastes nothing.

Same for any PDF, RTF or HEIC copy. Even in the text case, `set_text` replaces
the pasteboard wholesale, so a copy with both a text and an image flavor comes
back text-only. Silent, irreversible, on the default path.

**Fix:** snapshot and restore the full pasteboard with `NSPasteboard`, or skip
the round trip where a direct write is available.

## 15. [verified] Speech model downloads have no integrity check

`crates/teletype-speech/src/catalog.rs`, `commands.rs:1513-1651`

The LLM path is digest-pinned: all 8 EG-1 shards carry a SHA-256 verified
before the rename. The speech path has **no `sha256` field on `SpeechModel` at
all**, and both base URLs point at `huggingface.co/.../resolve/main/...`, a
mutable branch ref. The loop reads until EOF, never compares `size_mb`, then
emits `"verifying"` and renames. Nothing is verified.

Two failures: a dropped connection at 90% installs a truncated model and shows
100% Done; a compromised repo installs a crafted `.bin` straight into a GGML
model parser.

## 16. [verified] Intel Mac updates install an arm64 build

`.github/workflows/release.yml:226-227`

```python
platforms["darwin-aarch64"] = mac
platforms["darwin-x86_64"] = mac      # the same arm64 payload
```

`macos-latest` is arm64 and no universal target is passed. The signature check
passes, because the signature is genuine over the arm64 tarball, so the update
installs and the app will not launch. 100% of Intel-Mac updates ship a broken
app with a green signature.

**Fixed by removing the lie and then shipping the thing.** First the false
`darwin-x86_64` entry was deleted, so an Intel Mac got no update rather than a
broken one. Then a real x86_64 build was added, so the entry could be honest.

### Intel build (user: "universal, or separate Intel + Silicon, and can a separate Intel build work?")

**Separate builds, not a universal binary.** A universal `.app` would have to
carry a `llama-server` that runs on both architectures, and llama.cpp is
compiled per architecture, so "universal" means two llama-servers in one bundle
that is twice the size and cannot be code-signed as a single file. Two
artifacts is the smaller and separately-updatable answer.

Cross-compiled from the same Apple Silicon runner, so there is one macOS build
story rather than a separate Intel runner to keep alive.

**Verified locally, not assumed.** `cargo check --workspace --target
x86_64-apple-darwin` passes (2m11s), and `llama-server` cross-builds to
`Mach-O 64-bit executable x86_64`, 15,983,296 bytes, with both the CPU and
Metal backends.

The cross-build failed first, and the reason is worth keeping:

```
error: unknown target CPU 'apple-m4'
```

`GGML_NATIVE` is on by default, and it probes the **host** CPU and writes the
answer into the compile flags. Cross-compiling from this M4 wrote
`-mcpu=apple-m4` into an x86_64 compile, which clang rejects. `ggml-metal`
itself cross-compiles fine; it is the CPU backend only. The script now turns the
probe off for cross-builds and names the baseline (`-DGGML_AVX2=ON`, which every
Mac that can run macOS 15 has). Deliberately scoped to cross-builds: the arm64
build is native, its probe is correct, and changing its flags would change the
shipped Apple Silicon binary for no reason.

Two more arch-naming traps, both of which broke a build here:

- clang's `-arch` flag takes `arm64`, not Rust's `aarch64`.
  `clang: error: invalid arch name '-arch aarch64'`.
- `CMAKE_OSX_ARCHITECTURES` is turned into `-arch <value>` verbatim, so it needs
  the clang spelling too.
- `set -u` plus `"${EMPTY_ARRAY[@]}"` is an unbound-variable error on bash 3.2,
  which is what macOS ships and what the GitHub macOS runners use. The script
  would have failed in CI while working in my zsh-run shell.

### The updater manifest, which two payloads made ambiguous

With two macOS artifacts, the existing `sorted(glob(...))[0]` picks one *at
random*, because both payloads are called `Teletype.app.tar.gz`. So the fix is
three checks, each tested by a harness over eight scenarios:

- each build job writes an `ARCH` marker next to its own binary, and the
  manifest **refuses to publish** unless the marker matches the platform key.
  (`aarch64`, not `arm64`: `file` prints one, the target triple and the Tauri
  key use the other.)
- globs are scoped per artifact directory, and two payloads in one directory is
  an error rather than a coin flip.
- release asset names are checked for duplicates before upload, because two
  assets called `Teletype.app.tar.gz` would otherwise silently ship only one
  architecture. The Intel assets are renamed `Teletype-x86_64.*`; the arm64
  names do not change, so Apple Silicon users see no difference.

`darwin-x86_64` is now advertised **only** when the Intel artifact exists and
its own recorded architecture says x86_64. The Intel job is
`continue-on-error`, so a broken Intel build skips one manifest entry and
affects nobody else.

## 17. Text lands at the end of the field, reported as success

`crates/teletype-desktop/src/ax_text.rs:182-189`

## 18. A hung llama-server wedges dictation forever

`crates/teletype-inference/src/server.rs:344-350`

`stream.set_read_timeout(None)`. `params.timeout` is a deadline checked
*between* tokens, so it can only fire after a read returns. If the server
accepts the connection and then sends nothing, `stream.read()` blocks forever.
`chat_stream` runs on the pipeline thread, so every subsequent dictation
spawns another thread that also hangs.

## 23. A typed `/trigger` is silently dropped when a spoken snippet also matches

`crates/teletype-core/src/pipeline.rs:167-182`

```rust
let typed = protect::protect(&input_text, ...);
let spoken = protect_snippets_with(&input_text, ...);
if spoken.has_placeholders() { spoken } else { typed }
```

Both passes run on the *same* text and only one survives, so the other's
`values` map is discarded. Input `send it to /email and cc my email` with
`/email` and snippet `my email` configured: the model receives
`send it to /email and cc {{AUTOTEXT_0}}` and the final text is
`send it to /email and cc ali@example.com`. The trigger stays literal and the
user's intended address is never produced. The no-model path expands both,
which is why this only bites when a transform runs.

The comment above the branch, "The two namespaces are disjoint, so protect each
on the original text and keep the pass that matched anything", is the bug in
one sentence: disjoint namespaces do not mean disjoint *matches*.

# S2: users hit these often

# The pattern worth naming

Findings 1-4, 7, 8, 10 and 23 all have the same shape: **a guard exists and is
documented, but it does not evaluate the condition it was written for.**

- Six ITN passes "preserve spacing" by matching a leading `\s` and dropping it.
- The validator has a `Failure` taxonomy with no variant for the failure that
  actually happens (off-topic output).
- `PROJECT_BRAIN.md` §6 documents serde defaults that five structs do not have.
- `transform_skipped_no_model` is documented as "the UI must surface this" and
  can never be true on the path it was written for.
- The Insights screen reports a "speaking rate" it never measures.
- Two protection passes are documented as disjoint, so one result is discarded.

The general lesson, and the reason the tests here are shaped the way they are:
**a guard that cannot be observed failing is not a guard.** `tsc` cannot see a
serde field name, a unit test on `diff()` cannot see the caller's misuse of its
return value, and an assertion that a word is still present cannot see that it
is now welded to the wrong neighbour. Every test added in this pass exists to
make one of those failures visible: `text_integrity.rs` pins exact output,
`edit_watch_index.rs` pins the expression at the call site rather than the
callee, and `ipc_contract.rs` reads both sides of the wire.

# Round 2 (2026-09-28): what was fixed after the user's decisions

## The clipboard (user: "add a setting ... we don't wipe their files or images strictly")

`arboard` can read only text and images, and both `set_text` and `set_image`
replace the entire pasteboard. The old injector answered "what was on the
clipboard?" with "text, or an image, or nothing", and on the third answer it
called `clear()`. That is how copying a file in Finder and then dictating
destroyed the copied file.

- New `ClipboardGuard` trait in `teletype-core` (core stays platform-free) plus
  a `ClipboardSnapshot` that carries every representation, not just two.
- New `crates/teletype-desktop/src/clipboard.rs`: a macOS implementation over
  `NSPasteboard` that round-trips all `NSPasteboardItem`s and their
  representations, so a file copy, an image and rich text all survive.
- `clipboard.clear()` is now **never called**. A clipboard we cannot read is
  left exactly as found, which costs the user nothing.
- The dictated text is published as an *extra* pasteboard item alongside the
  restored ones, so it is **added to the system clipboard history** rather than
  replacing anything.
- New setting `keep_textOnClipboard` (default on), next to the existing
  `restoreClipboard`, with a UI toggle.
- `tests/clipboard_safety.rs` (6 tests) pins the rules.

Also fixed: `Phone_digit_runs` had the same space-eating defect as the other
ITN passes; `recovery`'s fixed-300 ms sleep and `teletype-eval`'s colliding
temp-dir name were both making CI flaky (1 failure in ~1 run in 3, now 8/8
clean).

## The speaking rate (user: "measure it properly ... check on internet and the ew folder")

Research is in `docs/research/speaking-speed-and-time-saved-claims.md`.
Summary of what changed and why:

- `DictationEntry` gained `duration_ms: Option<u64>`, measured on a
  **monotonic** clock (`Instant`) from the moment the mic opens to the moment it
  closes. Wall-clock `now_ms()` can jump backwards across an NTP correction and
  produce a negative duration. File transcription uses the file's own length;
  crash recovery uses the spool's length.
- `TYPING_WPM` is now **52**, not 40. 52 wpm is the mean of 168,000 volunteers
  across 136M keystrokes (Dhakal et al., CHI '18). The 40 wpm figure in wide
  circulation is a lower bound, and using it overstated the saving by a third.
- `Impact.words_per_minute` and `times_faster` are now `Option`, measured from
  real durations, and clamped to `MAX_PLAUSIBLE_WPM` (300; the fastest
  documented recitation is ~655, nothing spontaneous is near it).
- Takes shorter than `MIN_DURATION_FOR_RATE_MS` (1.2 s) are skipped, because
  mic open/close dominates them. `rated_takes` / `skipped_takes` are surfaced so
  the rate is never presented as covering more than it does.
- `time_saved_minutes` is computed in minutes from the same word count on both
  sides and floored at zero, which makes it **monotone by construction**. The
  old integer-division version was not: 149 words reported 3 min saved and 150
  words reported 2.
- The UI no longer prints a rate it cannot measure. It says
  "measured over N dictations" when it has data and falls back to
  "Based on your word count against a 52 wpm average typing pace" when it does
  not.

EnviousWispr, for reference, has no speed feature at all. It stores a
`duration` field that means different physical things per engine, never reads
it, and only sends the real one to telemetry.

## System AutoText: shipped (user: "yes please do both")

The brainstorm above proposed a deterministic context rule and a settings
switch. The user approved the rule and both were built. **There is no settings
switch**, and the reason is worth recording, because it was a deliberate
departure from the recommendation above.

### What shipped

`crates/teletype-core/src/autotext/disambiguate.rs`, a pure function with one
entry point:

```rust
pub fn entry_allowed(text: &str, start_idx: usize, phrase: &str) -> bool
```

Called from both `expand_snippets_with` and `protect_snippets_with`, so the
protection path (the one that ran first and handed `the payment{{AUTOTEXT_0}}
ends in March` to the model) is fixed at the same time. A third test,
`protected_autotext_placeholder_is_not_inserted_for_prose`, covers that path
separately rather than inferring it.

An ambiguous phrase expands when the utterance is 1-2 words, when a naming cue
is within two words before it, when it opens or closes the utterance, or when an
insertion marker follows it.

### Three things the prototype got wrong, found by writing the tests

The 13/13 prototype was a sketch. Three defects only appeared once the rule was
run against the real `DEFS` table:

1. **The ambiguous set could not be derived from "is this a common English
   word".** It puts `at sign` and `new line` in the same class, and they are
   opposites: "email at sign example dot com" is a real symbol request, while
   "start a new line for the address" is prose and is in the audit's own bug
   table. So single words are classified by a derived prose-word test, and the
   multi-word cases are an explicit list of the five phrases that read like a
   fragment of an English sentence (`new line`, `next line`, `line break`,
   `plus sign`, `minus sign`), with the criterion written down.
2. **A rejected phrase left its own prefix behind.** In "two plus sign two
   equals four" the two-word entry is rejected as prose, but the one-word entry
   `plus` sits at the same position, expanded anyway, and the output was
   `two + sign two = four`. Worse than either decision alone.
   `continues_into_ambiguous_phrase` now judges a one-word entry by the longer
   phrase the text continues into.
3. **`INSERTION_MARKERS` was too generous.** It started with `in`, `on`,
   `after`, `first`, `second` because "I need a comma here" is a request. Those
   are ordinary continuations, so "the quote in the article was wrong" counted
   as a request and the original bug came straight back. It is now `here`,
   `please`, `now`, `next`.

### Why no setting

The recommendation above said to keep a switch as a safety net. I did not add
one, because a switch would be a way to get the bug back, and:

- nothing that worked correctly before stops working. Every unambiguous request
  still expands, "full stop" is a multi-word phrase and is never affected, and
  `protected_symbol_requests_still_expand` asserts the preserved capability
  against the real table rather than asserting it in a comment.
- the defect was not a preference. Nobody wants `the payment. ends in March`.
- seven persisted settings already have no UI, and each one is a place a user
  cannot undo a decision.
- "full stop" and "insert a comma" are already the escape hatch, and they are
  the same words a user would reach for anyway.

A **custom** AutoText entry whose phrase is "comma" is deliberately exempt: the
user typed that trigger in on purpose, so it fires wherever it appears.

### The Jev/Kev question, settled

`docs/research/jev-kev-for-symbol-disambiguation.md` is the full write-up. The
short version: a discriminative decision model is the right *shape* and the
wrong *runtime* for this codebase. Kev's only implementation is Python with
torch/MLX on Qwen3.5/3.8, which has no llama.cpp path, and Teletype's LLM
contract is built on not having one (D002 linked-llama.cpp, D003
local-first/no-cloud). Its measured latency would be fine (149 ms on an M5), so
latency was never the reason.

What was taken from it is the decision point: one small pure function with a
narrow surface, which a calibrated model can replace later without touching the
AutoText engine.

# Round 4 (2026-09-28): two user-reported defects

Both were reported from real use, not from reading code. Both had a cause that
none of the existing 557 tests could see, and in both cases the first plausible
explanation was wrong.

## 1. The clipboard pastes the previous text, again and again

**Reported as:** *"it is taking the previous clipboard text and it is pasting it
again and again"*, described as critical.

`arboard::set_text` does call `clearContents`, so the paste itself was correct
and the clipboard round trip was not obviously at fault. The real cause was the
**order** in which `MacClipboardGuard::restore` wrote items back.

`NSPasteboard` pastes **item 0**. The restore appended the dictation as the
*last* item:

```rust
for item in &snapshot.items { items.push(nsi) }   // item 0 = the user's old copy
if let Some(text) = extra { items.push(make_text_item(text)) }  // item LAST
```

So after every dictation the user's previous copy sat at the front where every
paste read it, and the dictation was on the pasteboard but unreachable without
Paste Special. The "again and again" half is the compounding: each restore
rewrote the whole snapshot plus a new dictation item, and the next dictation
snapshotted that, so the pasteboard grew by one item per dictation, forever,
with the oldest text still at the front.

**Fix.** The policy moved into `ClipboardSnapshot::restored_with`, a pure
function in `teletype-core` so it is testable without a pasteboard:

- the dictation goes **first**, so Cmd+V after dictating gives the dictation;
- the user's items follow in their original order, so a copied file, image,
  rich text or multi-selection is still whole and still pasteable;
- items we added carry a `org.teletype.dictation` marker and are dropped from
  the next snapshot, so nothing accumulates;
- a 16-item cap as a backstop.

`clipboard_safety.rs` grew 7 tests, including one that runs 200 dictation
round-trips through the policy and asserts the pasteboard holds exactly two
items at the end. The bug was reintroduced deliberately to confirm the tests
fail (`left: Some("the old clipboard")`, `after 200 dictations the pasteboard
held 201 items`) before the fix was kept.

## 2. EG-1 selected, but the polish never ran

**Reported as:** *"even after selecting the model EG1 it's still not detecting
value and it's not polishing"*, on a sentence that should have become a list.

The list formatting was never the problem. `format_spoken_lists` produces the
right output for both the punctuated and unpunctuated forms of the exact
sentence, and the polish gate returns `needs_cleanup` for both, so the dictation
reaches the transform stage. All four are now pinned as acceptance tests in
`engine.rs::real_world_repro`.

The cause was the model never loading, and the log said only:

```
Error LLM first-use load failed for 'eg-1': llama-server exited early with
signal: 9 (SIGKILL) (log: .../teletype-llama-server-eg-1-59282.log)
```

with a **0-byte** log. That is the tell. The real cause, confirmed from
`~/Library/Logs/DiagnosticReports/`: `EXC_CRASH`, `signal: SIGKILL (Code Signature
Invalid)`, `bug_type 309`, no frames.

`scripts/build-llama-server.sh` used `cp` to install the binary. `cp` writes
into the existing inode, and a `llama-server` from an earlier dev loop was
running from that path. Overwriting the inode of an executing file leaves one
macOS refuses to execute. `file` still reported a valid Mach-O and the
executable bit was still set, so nothing that existed would have caught it.

Verified in both directions: `cp` onto a file a process is exec'ing from makes
the next exec exit 137, and `mv`-ing a fresh temp file into place does not, with
the running server undisturbed. `codesign --force --sign -` on the same bytes
also fixes it, which is how the inode state was identified as the cause rather
than the content.

**Fix.**
- The script installs with a temp file plus `mv -f`.
- The script now **execs the binary it just installed** and fails with the
  `codesign` remedy if it cannot start. The size check already there could not
  have caught this: the file is a perfectly good 14 MB Mach-O.
- `wait_until_ready` names the cause whenever the child dies with a 0-byte log,
  instead of a bare exit status, and points at `pgrep -fl llama-server`.

This was self-inflicted: the script rewrite in this same session added a size
check and kept the `cp`.

## 3. A lying test the new work exposed

`StreamingMock` returned a bare `"Hello"` for a 7-word input, and its test
asserted the validator **must accept** it:

```rust
assert!(result.transformed, "validator must accept the streamed output");
```

The `OffTopic` check added earlier in the session correctly rejects an output
sharing no content word with the input, so this started failing. The test was
the thing that was wrong: it made a nonsense mock the specification, which is
the failure mode the `protected_*` / `regression_*` convention exists to
prevent. The mock now returns a real rewrite of the input, streamed word by
word, and the test asserts the tokens arrive interleaved and in order.

## Verification

569 tests pass, 0 fail, 2 ignored. `cargo fmt --all --check` clean, clippy at
the 74-warning baseline, notices and manifest scenarios pass, all four shell
scripts parse.

# Round 6 (2026-09-28): previous takes repeated inside new ones (Terminal.app)

## Symptom

Dictating three takes into a normal terminal produced `t1 | t1t2 | t1t2t3`:
take 2's insert contained take 1 plus take 2 joined with no space, take 3's
contained all three. Reported as very critical, and rightly so: every take
re-speaks everything said before it.

## What the evidence ruled out, in order

1. **Speech recognition.** `dictation.json` recorded each take separately and
   correctly. The ASR output was never wrong.
2. **The clipboard and the double-paste bug.** The log showed exactly one
   `direct write ok` per take, with char counts matching each take exactly
   (150, 41, 117). No clipboard fallback fired, nothing injected twice.
3. **The audio buffer.** Dead once (1) held: the transcripts were already
   correct per take.

## Root cause

`ax_text::insert_into` did whole-value read-modify-write: read the field's
entire value, splice the new text at the caret, write the entire string back.
That assumes a value-set means *replace*. Terminal.app's AX text area treats a
value-set as *type this*: it appends the string to the display while reporting
the set string back as its value.

So take 2 read `t1`, wrote `t1t2` (appended: display `t1t1t2`... precisely,
display `t1` + `t1t2`), take 3 read `t1t2`, wrote `t1t2t3`. And the read-back
`back == next` matched every time, because the parrot returns what was set.
The verification designed to catch silent discards was defeated by an app that
lies affirmatively, and the duplication was logged "direct write ok".

The `edit watch: Unchanged` lines fit too: `diff` is substring search with
end-anchoring, so a value ending with the insert reads as untouched.

## Fix

Tier 1 now inserts via `AXSelectedText` (selection replacement) and sends only
the new text. Old content is read solely as the verification baseline, never
as write material, so there is nothing for an appending app to duplicate. The
worst case is one copy or zero copies, never a growing concatenation.

`classify_write` is the pure decision function: Exact when the read-back
matches a true insert (including the slice-at-caret case for normalising
apps), Refused only when the value is byte-identical (silent discard, so the
clipboard fallback cannot double anything), Normalized for changed-but-
unexpected (smart quotes, or a parroting terminal). Only Refused reaches the
clipboard. No cascade back to value-set: an app that silently discards
selection-set but appends on value-set would re-open the bug through it.

## Tests

`whole_value_resend_duplicates_in_a_terminal_and_selection_does_not` drives a
fake append-and-parrot app both ways: the old strategy must produce the user's
exact pasted shape `t1|t1t2|t1t2t3` (pins the bug's shape, documents the why),
the new strategy must produce `t1|t2|t3` with every take landed and no
fallback. Plus unit pins for each `classify_write` arm, including the parrot
case resolving to Normalized rather than a second paste.
