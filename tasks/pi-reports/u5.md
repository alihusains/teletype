## Fix 1 (u1 finding U1-8): Insights CTAs never render

File: `ui/src/App.tsx` (one line)

`<InsightsScreen />` was rendered without the `onNavigate` prop, so every
conditional CTA in the screen ("Tune AI Polish", "Dictionary", "AutoText",
"Styles", "Manage snippets", and the "Open Models" button on the
polishStatus warning banner) stayed hidden because each is gated on
`onNavigate && (...)`.

The other cross-screen links (HomeScreen, TransformsScreen) already pass
`onNavigate={(s) => setScreen(s as Screen)}`. I passed the identical handler:

```diff

+            <InsightsScreen onNavigate={(s) => setScreen(s as Screen)} />
```

`InsightsScreen`'s signature is `({ onNavigate }: { onNavigate?: (screen: string) => void })`
(ui/src/screens/InsightsScreen.tsx), so the cast matches the existing pattern.

## Fix 2 (u2 finding U2-R2): recorded hotkeys render "Command" not "Cmd"

File: `ui/src/components/HotkeyRecorder.tsx`

`displayHotkey` looked each `+` segment up in `MODS`, which only covers the
short forms (`Cmd`, `Ctrl`, `Alt`, `Shift`, `Fn`, `Space`). But
`ui/src/lib/hotkeyCapture.ts` emits the long modifier names from
`ModifierName` ("Shift" | "Control" | "Alt" | "Command") via
`chordToHotkey`, so a recorded chord like `Command+Shift+M` rendered as
"Command ⇧ M".

Added a case-insensitive alias map and canonicalize each segment before the
symbol lookup:

```ts
const MOD_ALIASES: Record<string, string> = {
  command: "Cmd",
  control: "Ctrl",
  option: "Opt",
};

export function displayHotkey(hotkey: string): string {
  if (typeof hotkey !== "string" || !hotkey) return "";
  return hotkey
    .split("+")
    .map((p) => {
      const canonical = MOD_ALIASES[p.toLowerCase()] ?? p;
      return MODS[canonical] ?? canonical;
    })
    .join(" ");
}
```

Behavior:
- `Command` -> `Cmd` -> ⌘, `Control` -> `Ctrl` -> ⌃, `Option` -> `Opt`
  (displays as the literal "Opt"; MODS has no symbol entry for it).
- Case-insensitive for the long names: `COMMAND`, `control`, etc. also map.
- `Shift` is untouched (already a MODS key, so it still maps to ⇧); short
  forms `Cmd`/`Ctrl`/`Alt`/`Fn`/`Space` and bare keys (`A`, `F12`, ...)
  behave exactly as before.
