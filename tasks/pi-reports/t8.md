## Summary

The decided 0.8B prompt design is implemented and all four verification
commands pass (one test needed a one-line fix). Live probes A-E against the
real 0.8B confirm the lean Polish prompt works for email/prose/generic

editing, and it can echo the control line verbatim into the output (confirmed
to reach the user).

## Live probe, cases A-E (raw model output verbatim)

The probe regex-extracted `QWEN08_POLISH_SYSTEM_PROMPT`,
`QWEN08_GENERIC_RULES`, and `REWRITER_INSTRUCTION` from the edited Rust
source, mirrored the engine's message shapes (system + control-line user for
Polish; single user message for the generic path), and sent each case to the
0.8B at temperature 0 with the engine's stop sequences and
`chat_template_kwargs {"enable_thinking": false}`. Raw model output is shown
verbatim; deterministic post-processing (engine-side) is noted separately.

### Case A: email context, casual, longish transcript with spoken numbers
Expect: no Subject/Dear/Best regards, numbers normalized to `$450` form.

Input:
```
hey so just wanted to follow up about the invoice from last week the total was four hundred and fifty dollars and i think you said you would settle it by friday oh and by the way the signed copy is at example dot com slash invoices so you can download it before the end of the month
```
Control line: `[Styling: casual] [Structure: prose] [Context: email]`

Raw model output (verbatim, finish_reason: stop):
```
hey, just wanted to follow up about the invoice from last week. The total was $450, and I think you said you'd settle it by Friday. Also, the signed copy is at example.com/slash/invoices, so you can download it before the end of the month.
```
Result: PASS. No email framing (no Subject/Dear/Best regards). `$450`
present. Minor: `example dot com slash invoices` became
`example.com/slash/invoices` (the word "slash" was half-converted to `/` but
the word also remained). See model limit L4.

### Case B: same transcript + override "Use British spelling"
Expect: organise/apologise style words via the deterministic word map.

Input:
```
hey so just wanted to follow up about the invoice from last week the total was four hundred and fifty dollars and i think you said you would settle it by friday i apologize for the confusion and i will organize the documents and the signed copy is at example dot com slash invoices so you can download it before the end of the month

Extra instruction from the user: Use British spelling
```
Control line: `[Styling: casual] [Structure: prose] [Context: email]`

Raw model output (verbatim, finish_reason: stop):
```
hey so just wanted to follow up about the invoice from last week. the total was four hundred and fifty dollars, and i think you said you would settle it by friday. i apologize for the confusion. i will organize the documents and the signed copy is at example.com slash invoices. you can download it before the end of the month.
```
Result: the raw model did NOT apply British spelling (kept `apologize`,
`organize`). This is the documented model limit L1: the 0.8B cannot apply the
override from the prompt, so the engine's deterministic word map
(`apply_british_spelling`) converts them on the output when the override asks
for it. Separately, the override degraded other rules in this run: no
capitalization and no `$450` (the same transcript WITHOUT the override
produces `$450` and full capitalization, see follow-up probe). See model
limit L3.

### Case C: lists context, transcript of several list items
Expect: each item on its own line starting with `- `.

Input:
```
before the launch we need to update the changelog email the beta users check the status page and bump the version number
```
Control line: `[Styling: semi-formal] [Structure: lists] [Context: general]`

Raw model output (verbatim, finish_reason: stop):
```
Before the launch, we need to update the changelog email. Beta users should check the status page and bump the version number.
```
Result: FAIL against the expectation. The model returned prose, not a
bulleted list, despite `[Structure: lists]`. Re-tests with clearer list input
(sequential markers, an explicit numbered list, a shopping list) also returned
prose and, in one case, echoed the control line. See model limits L2 and L5.

### Case D: prose context where the model tends to emit a leading `- `
Expect: no leading bullet, first letter capitalized.

Input:
```
um so basically move the meeting to friday at 2 pm so that everyone can join and we can go over the new design
```
Control line: `[Styling: semi-formal] [Structure: prose] [Context: general]`

Raw model output (verbatim, finish_reason: stop):
```
um, so basically move the meeting to Friday at 2 pm so that everyone can join and we can go over the new design.
```
Result: PASS. No leading bullet. The raw lead is lowercase (`um`), but the
engine's `capitalize_leads` (in `qwen08_polish_postprocess`) capitalizes the
line lead, so the final output is `Um, so basically ...`. The spurious
leading-bullet safety net (`strip_single_leading_bullet`) did not trigger on
this input; it is covered by the unit test
`qwen08_polish_prose_strips_a_spurious_leading_bullet`.

### Case E: generic transform (non-Polish) request on 0.8B
Expect: only the edited text, no commentary.

Transform: `builtin-rewriter`, user instruction `make it shorter and
friendlier`, slim generic rules, `LANGUAGE: en`.

Input:
```
so i was thinking we should maybe push the meeting to thursday because the design review isnt done and honestly the team needs more time to look at the mockups
```

Raw model output (verbatim, finish_reason: stop):

### F1 detail (control-line echo reaches the user)

On this input the 0.8B deterministically (3/3 runs, temp 0) echoes the
control line as the first line of its output:

```
in:  for the party i need to buy milk, buy eggs, buy bread, and buy cheese
control: [Styling: casual] [Structure: lists] [Context: general]
out: [Styling: casual] [Structure: lists] [Context: general]
      For the party, I need to buy milk, eggs, bread, and cheese.
```

I verified against the real validator with a temporary integration test
(added, run, then removed): `validate_polish` on that output with the default
40% change ceiling returns `Transformed` with the control line intact (change
share is about 33%, under the 40% ceiling; the control line matches none of
the hardcoded instruction-echo probes, is not a preamble, and the growth is
under the 4.0x cap). `qwen08_polish_postprocess` only capitalizes line leads
and does not remove lines, so the control line reaches the user verbatim.
`strip_control_characters` in `pipeline.rs` strips ASCII control characters,
not the control line.

Suggested minimal fix (for the lead to sequence): strip a leading control line
from the 0.8B Polish output in `qwen08_polish_postprocess` (it is a known,
fixed-format first line), or add a control-line probe to the validator's
instruction-echo check.

## Documented model limits

- **L1 British spelling.** The 0.8B cannot apply a British-spelling override
  from the prompt in any placement (system addendum, user tail, or explicit
  mapping all failed on long transcripts). The decided fallback is the
  deterministic word map (`BRITISH_SPELLING_MAP` / `apply_british_spelling`),
  which runs on the engine output when the override asks for it. Probed in
  case B (raw model kept `apologize`/`organize`).
- **L2 List structure.** The 0.8B does not reliably follow
  `[Structure: lists]` to emit `- ` bullets; it returns flowing prose.
  Probed across four list inputs (two re-tested for determinism); no run
  produced a bulleted list. The Structure=lists toggle is therefore not
  honored by the 0.8B.
- **L3 Override degrades core editing.** Adding a user override to the 0.8B
  Polish path suppresses the model's core editing: the same transcript with
  the override produced no capitalization and no `$450`, while the same
  transcript without the override produced both (deterministic, temp 0). The
  word map and `capitalize_leads` mitigate British spelling and
  capitalization respectively, but number normalization is not
  deterministically recoverable when the override is present.
- **L4 URL `slash` half-normalization.** Spoken `slash` inside a URL is
  converted to `/` but the word also remains (`example.com/slash/invoices`).
  Minor.
- **L5 Control-line echo.** The 0.8B can echo the control line verbatim into
  the output (deterministic on at least one input). This is the cause of
  finding F1 and is not currently guarded.

## What the lead must sequence

- **F1 (control-line echo) is the only user-facing defect.** It needs a
  deterministic guard (strip the leading control line in
  `qwen08_polish_postprocess`, or a validator probe) and a regression test.
  It is a shared-path change (the validator is used by all models), so it
  should be sequenced and reviewed, not left in this branch silently.
- **L2 (lists not honored)** is a product-behavior gap for the 0.8B. Decide
  whether to (a) accept prose for the 0.8B lists toggle, (b) disable/hide the
  lists structure option for the 0.8B, or (c) attempt a deterministic
  prose-to-list pass. This is a product decision, not a code fix I should
  make.
- **L3 (override degradation)** is an accepted consequence of honoring the
  override at the user tail. If number normalization with an override matters,
  it needs a design decision (the override placement was chosen as the one the
  0.8B actually reads).
- No changes were made to shared components beyond what the decided
  implementation already contains. The only edit I made was the one-line test
  fix in `qwen08_prompt.rs` required to make `cargo test qwen08` pass.

## F1 fix (t8-f1, 2026-11-10)

Fixed on the engine side as suggested, without touching the shared
validator, so the change is scoped to the 0.8B Polish path only.

What changed (all in `crates/teletype-core/src/transforms/engine.rs`):

- New pure helper `strip_echoed_control_line` (engine.rs:338). If the first
  line of the model output, trimmed, equals
  `ctx.s1_control.control_line()`, or is a near-miss echo (starts with
  `[Styling:` and contains `[Structure:` and `[Context:`), it removes that
  one line only. Never more than one leading line; the rest of the text is
  never touched.
- `qwen08_polish_postprocess` (engine.rs:358) now runs the strip first,
  before the existing prose shaping.

`Qwen08Recorder`):

  probe shape, verbatim control line as first reply line.
