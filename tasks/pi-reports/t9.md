## Summary (3 lines)

Pressing any transform hotkey on selected text now shows the pill as
"Transforming…" with the agentic sparkle while the model works, and the pill
goes away once the result is pasted (or after a short error note on failure).
The hotkey path reuses the existing dictation pill machinery (`overlay::update`
+ `overlay::set_interactive`), mirroring `dictation.rs::show_with`, and never
clobbers a live dictation take. No UI changes were needed: `pillMachine.ts`
already refines any message starting with "transform" into the streaming phase,
and `pill.tsx` renders `AgenticSparkle` for that phase.

## What changed and why, per file

### `crates/teletype-desktop/src/commands/transforms.rs` (only file changed)

Added `use teletype_core::state::{PillState, UiState};`.

New private helpers (kept in-file, no new module, no framework):

- `enum PillStage { Start, Success, Failure }`: a point in the transform pill
  lifecycle.
- `fn take_in_flight(ui_state: &UiState) -> bool`: true while a dictation take
  owns the pill (`Listening`/`Transcribing`/`Transforming`/`Inserting`). Uses
  the existing `AppState.dictation_state` phase (the same `UiState` the
  dictation controller broadcasts on every phase change), so no new shared
  state was invented.
- `fn pill_state_at(stage, take_in_flight, failure) -> Option<PillState>`: the
  pure decision. Returns `None` while a take is in flight (never clobber);
  otherwise `Processing { "Transforming…" }` for Start, `Idle` for Success, and
  `Processing { <note> }` for Failure (degrading to "The transform failed" when
  no note is given).
- `fn push_pill_at(app, state, stage, failure) -> bool`: the thin wrapper that
  mirrors `dictation.rs::show_with`: reads `settings.pill_position.resolve()`
  and `settings.always_show_pill`, calls `overlay::update`, then
  `overlay::set_interactive(app, interactive_for(&pill, alert))` where `alert`
  is true only for the Failure note (clickable, like the dictation `flash`).
  The Start cue is click-through (`alert=false`), like a dictation progress
  label.
- `fn schedule_pill_hide(app)`: after a Failure note, a plain spawned thread
  sleeps 2 s, re-checks `take_in_flight` via `app.try_state::<AppState>()`, and
  pushes `Idle` only if no take has taken over the pill. Deliberately a simple
  timer, not a framework, per the task.

`transform_selection_with_text` (signature and Tauri contract unchanged):

- After the selection and transform lookups pass and before `spawn_blocking`,
  it calls `push_pill_at(&app, &state, PillStage::Start, None)`. The
  no-selection and transform-not-found errors return before any pill push.
- The work closure now moves a `work_app = app.clone()` so the original `app`
  stays available for the exit paths (the closure previously moved `app`).
- The single `.await.map_err(...)?; let polished = handle?;` was replaced by an
  exhaustive `match` on the `Result<Result<String, String>, JoinError>` so every
  failure path (inner model error and join/panic error) flashes the note and
  schedules the hide before returning the error.
- Both success exits (direct-AX write, and the clipboard-paste fallback) call
  `push_pill_at(..., PillStage::Success, None)` (Idle) before returning `Ok`.
- The paste-refused exit flashes "Couldn't replace the selection in that app."
  and schedules the hide before returning the error.

Tests (added to the existing `#[cfg(test)] mod tests`, no real AX/LLM):

- `take_in_flight_tracks_dictation_phases`: Idle/Message are not in flight;
  Listening/Transcribing/Transforming/Inserting are.
- `pill_states_cover_the_transform_lifecycle`: Start shows the "Transforming…"
  cue (suppressed when a take is in flight), Success goes Idle (suppressed when
  a take is in flight), Failure flashes the note (suppressed when a take is in
  flight), and a missing note degrades to a generic message.
- `deferred_hide_respects_a_take_that_starts_late`: the 2 s hide only fires
  while the transform still owns the pill.

## Reported-not-fixed / notes for the lead

- No changes were made outside `crates/teletype-desktop/src/commands/transforms.rs`.
  `shortcut_manager.rs` (also owned) needed no edit because `dispatch` already
  routes through `transform_selection_with_text`.
- Known narrow edge (accepted per the task's "simple timer, not a framework"):
  two transform hotkeys fired back-to-back could each schedule a 2 s hide
  timer; a stale timer from a failed transform could, in that rare overlap,
  hide a second in-flight transform's cue early. The second transform still
  runs and pastes, and pushes its own Idle on completion, so it self-heals. A
  dictation take is fully protected because every push (including the timer)
  re-checks `take_in_flight`.
- The `pill-state` event and the `AgenticSparkle` rendering already exist and
  were verified by reading `ui/src/pillMachine.ts` and `ui/src/pill.tsx`; no UI
  file was edited (pill files are reserved).
